# File formats (versioned contracts)

Three files make up the system of record. All are versioned; all changes to
their meaning follow semver on the engine.

## 1. Artifact file — frontmatter schema v1

Every `*.md` under a configured root (non-recursive; `README.md` excluded) is
one artifact. YAML frontmatter is the recipe; the body is the content (for
`kind: inline` the body IS the fingerprinted content).

```yaml
---
canonweave: 1                    # REQUIRED — schema version key
id: acceptance-criteria          # REQUIRED — stable identity, NOT the filename
type: acceptance-criteria        # REQUIRED — must exist in the ontology
title: Acceptance Criteria       # optional
source:
  kind: inline                   # inline | repo | url | <plugin kind>
recipe:
  ingredients: [requirements]    # what this artifact derives from (ids)
  build: "One Given/When/Then per requirement."
reconciled:
  requirements: "sha256:..."     # ingredient fingerprint at last human review
owner: product                   # optional, free-form (CODEOWNERS in practice)
status: present                  # present | placeholder (default placeholder)
provenance:
  issue: 123                     # optional explicit GitHub issue binding
---
(body)
```

Unknown top-level keys are preserved on rewrite (forward compatibility).
`id` must match `^[a-z0-9][a-z0-9._-]*$`.

### JSON Schema (informative rendering of schema v1)

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "Canonweave artifact frontmatter, schema v1",
  "type": "object",
  "required": ["canonweave", "id", "type"],
  "properties": {
    "canonweave": { "const": 1 },
    "id": { "type": "string", "pattern": "^[a-z0-9][a-z0-9._-]*$" },
    "type": { "type": "string" },
    "title": { "type": "string" },
    "source": {
      "type": "object",
      "properties": { "kind": { "type": "string" } },
      "additionalProperties": true
    },
    "recipe": {
      "type": "object",
      "properties": {
        "ingredients": {
          "type": "array",
          "items": { "type": "string", "pattern": "^[a-z0-9][a-z0-9._-]*$" }
        },
        "build": { "type": "string" }
      }
    },
    "reconciled": {
      "type": "object",
      "additionalProperties": { "type": "string" }
    },
    "owner": { "type": "string" },
    "status": { "enum": ["present", "placeholder"] },
    "provenance": {
      "type": "object",
      "properties": { "issue": { "type": ["integer", "null"] } }
    }
  },
  "additionalProperties": true
}
```

## 2. The YAML subset

The engine ships its own zero-dependency YAML-subset parser. Supported:

- maps: `key: value`, or `key:` followed by a deeper-indented block
- block lists of **scalars**: `- item`
- inline lists: `[a, b, c]` (items are scalars; quote items containing commas)
- scalars: `null` / `~` / `true` / `false` / numbers / `"double"` / `'single'` / raw
- `{}` — the empty map
- comments (`#` at line start or after whitespace), blank lines
- indentation with spaces only; siblings share one indent

**Not supported by design** (parse error): tabs, anchors/aliases, multi-document
streams, block scalars (`|`, `>`), quoted keys, flow maps other than `{}`,
lists of maps. Zero-dependency discipline beats YAML coverage; the subset is
exactly what the schema above needs.

## 3. Fingerprint spec (v1)

```
fingerprint = "sha256:" + sha256hex( normalize(content) )
normalize   = CRLF -> LF          # nothing else: no trim, no NFC, no BOM strip
```

Windows and unix checkouts of the same content fingerprint identically.
Changing `normalize()` flips every fingerprint in the wild: it is a MAJOR
version change of this contract, never a patch.

## 4. graph.json

Generated by `build`, deterministic (same inputs -> byte-identical output; no
clocks — `generatedAt` is always `null`), committed by default so PR diffs
show trace-state changes. Never hand-edit; regenerate on merge conflict.
On teams with Windows checkouts, pin its line endings in `.gitattributes`
(`docs/trace/graph.json text eol=lf`) so `autocrlf` never rewrites the
committed bytes — the graph is always written with LF.

```
{
  canonweave: 1,
  generatedAt: null,
  defaultProfile: "ready-to-build",
  nodes: [ { id, type, tier, status, source{kind,resolver,...}, fingerprint,
             ingredients[], reconciled{}, suspectIngredients[],
             provenance{issue}, unresolved, resolveError } ],
  edges: [ { from, to } ],                       # from=ingredient, to=dependent
  suspects: [ { node, ingredient, expected, actual } ],
  gaps: [...],                                   # the default profile's gaps
  gates: { <profile>: { pass, reasons[], gaps[] } }
}
```

## 5. CLI exit-code contract

| code | meaning |
|---|---|
| 0 | gate pass / verb success |
| 1 | gate fail — suspects and/or coverage gaps |
| 2 | config or ontology error (bad frontmatter, illegal edge, unknown type/key) |
| 3 | resolve error — a source is unreachable and has no committed cache |

Precedence when several apply: 2 (config) beats 3 (resolve) beats 1 (gate).
`check` is a report: it exits 0 on content findings and non-zero only when the
repo itself is misconfigured.

## 6. Validation error codes (TW_*)

Stable machine codes; part of the public contract.

| code | thrown when |
|---|---|
| TW_CONFIG_NOT_FOUND / TW_CONFIG_YAML / TW_CONFIG_SHAPE | canonweave.yml missing / unparseable / not a map |
| TW_CONFIG_UNKNOWN_KEY | unknown top-level config key |
| TW_CONFIG_ROOTS / TW_CONFIG_ONTOLOGY / TW_CONFIG_GRAPH / TW_CONFIG_GATE | malformed path/profile fields |
| TW_CONFIG_DRAFTER / TW_CONFIG_DRAFTER_BACKEND / TW_CONFIG_DRAFTER_CMD | malformed drafter block |
| TW_CONFIG_DRAFTER_MODEL | drafter backend `openai` without a `model` (no universal default) |
| TW_CONFIG_SYNC / TW_CONFIG_RESOLVERS | malformed sync / resolvers block |
| TW_SCHEMA_NO_FRONTMATTER / TW_SCHEMA_YAML | artifact missing/unparseable frontmatter |
| TW_SCHEMA_MISSING_VERSION / TW_SCHEMA_UNSUPPORTED_VERSION | `canonweave:` key absent / wrong |
| TW_SCHEMA_MISSING_ID / TW_SCHEMA_BAD_ID / TW_SCHEMA_MISSING_TYPE | identity fields |
| TW_SCHEMA_BAD_SOURCE / TW_SCHEMA_BAD_RECIPE / TW_SCHEMA_BAD_INGREDIENTS / TW_SCHEMA_BAD_BUILD | source/recipe shape |
| TW_SCHEMA_BAD_RECONCILED / TW_SCHEMA_BAD_STATUS / TW_SCHEMA_BAD_PROVENANCE | reconciled/status/provenance shape |
| TW_ONTOLOGY_NOT_FOUND / TW_ONTOLOGY_YAML / TW_ONTOLOGY_SHAPE / TW_ONTOLOGY_VERSION | ontology file problems |
| TW_ONTOLOGY_TIERS / TW_ONTOLOGY_TYPES / TW_ONTOLOGY_TYPE_SHAPE / TW_ONTOLOGY_TYPE_TIER / TW_ONTOLOGY_TYPE_INGREDIENTS | ontology contents |
| TW_ONTOLOGY_LEGACY_REQUIRED | prototype-era `requiredForGate` (see gate-profiles.md) |
| TW_ONTOLOGY_NO_PROFILES / TW_ONTOLOGY_PROFILE_SHAPE / TW_ONTOLOGY_PROFILE_TYPE / TW_ONTOLOGY_UNKNOWN_PROFILE | gate profiles |
| TW_ROOT_NOT_FOUND / TW_DUPLICATE_ID / TW_TYPE_UNKNOWN | artifact loading |
| TW_EDGE_UNKNOWN_INGREDIENT / TW_EDGE_ILLEGAL | derivation edges |
| TW_SOURCE_UNKNOWN_KIND | source.kind with no builtin or plugin resolver |
| TW_PLUGIN_LOAD / TW_PLUGIN_SHAPE / TW_PLUGIN_COLLISION | resolver plugin loading |
| TW_NO_SUCH_ARTIFACT / TW_NO_PROPOSAL / TW_PROPOSAL_IS_BRIEF / TW_PROPOSAL_PARSE | reconcile flow |
| TW_INIT_NO_TEMPLATE / TW_INIT_EXISTS / TW_INIT_COPY | init flow |
| TW_CLI_USAGE / TW_NOT_YET | CLI usage / WS4+WS6 stubs |
| TW_RESOLVE | ResolveError (exit 3): unresolved node(s) without cache |
